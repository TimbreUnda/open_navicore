# Build Open NaviCore

Three commands, from the repository root (CMake underneath; a top-level
Makefile is the only front end):

```sh
make          # the product for the radio, build/qnx/
make ifs      # navigation.ifs, build/qnx/ifs/navigation.ifs
make test     # host tests and contract checks, build/host/ (ctest; CI)
```

Run `make test` on every change and `make` before any deploy. Nothing else
is needed; there are no other targets.

## What `make` builds (build/qnx/)

| File | What |
|---|---|
| `libNaviCore.so` | the provider (loaded by the stock `nv_navigation`) |
| `libOpenNaviBackendOsmAnd.so` | the OsmAnd backend (map, search, routing, guidance, UI) |
| `libOpenNaviBackendReference.so`, `libOpenNaviBackendOutboundTest.so` | reference backends (SDK sample, tests) |
| `tests/navicore_smoke`, `tests/plugin_smoke`, `tests/osmand_*_smoke` | on-target smoke programs |

One toolchain builds all of it: the GCC 8.5 ARM/QNX cross compiler from the
OsmAnd QNX build with the QNX 6.6 SDK's sysroot and binutils
(`cmake/qnx-armv7.cmake`). After each link a check runs: provider exports,
SONAME and Thumb bits (`tests/check_elf.sh`), the ARM argument passing of the
recovered entry points and callback wrappers (`tests/check_arm_abi.py`), the
plugins' ELF/dependency profiles. A failing check fails the build.

Toolchain locations (make variable or environment; the defaults are the
workspace that holds this repository, so set them from a linked worktree):

| Variable | What |
|---|---|
| `QNX_SDK` | QNX 6.6 SDK (`tools/qnx660-sdk` in the workspace) |
| `QNX_HOST_LIBS` | host libraries the SDK binaries need (`tools/qnx-host-libs`) |
| `OSMAND_QNX_ROOT` | the OsmAnd QNX build tree (`osmand-qnx-build`): compiler, core, Qt |
| `IFSBUILD_DIR` | ifs-build checkout (`ifs-build`), for `make ifs` |

`make ifs` writes two things (2026-10-28):

- `build/qnx/ifs/navigation.ifs` (~0.8 MB): the provider, its config, `boot.sh`
  and `50-navicore.pre`; the slot's `50-navicore.ifs` on the radio.
- `build/qnx/navicore-data/navicore/`: the backend `libOpenNaviBackendOsmAnd.so`,
  OsmAnd core and its resource bundle (`OSMAND_RESOURCES_BUNDLE`, default next to
  the core in the OsmAnd build) as plain files for the slot's data dir; the image
  links them into `/open-navicore` at boot. They left the image on 2026-10-24
  (boot time). Maps and other data are in neither.

Install: skill `deploy-open-navicore` (a backend change is the backend file only).

Build trees on the D: drive fail at configure (`configure_file ... Operation not
permitted`): build into a Linux path with `BUILD=<dir>` or from a clone there. A
linked worktree has no `third_party/lvgl` checkout; copy the main checkout's
(same commit) into the clone.

`make ifs` also needs `STOCK_NV_NAVIGATION_CFG=<factory nv_navigation.cfg>`
once (QR39.5, SHA-256 `c889c2b4…d680e`, not committed; take it read-only
from the firmware dump's root partition, `pas/scfg/nv_navigation.cfg`).
Settings are remembered in the build tree. Use `BUILD=<dir>` to build
elsewhere.

Inspect an image without the radio:
`python3 <workspace>/tools/qnx_ifs.py build/qnx/ifs/navigation.ifs list`.

## Host tests

`make test` runs about two dozen ctest tests: provider smoke/lifecycle/
stress, plugin loader tests, the OsmAnd backend's session, UI, camera,
labels and vector tests, and the contract checks (contracts vs sources,
symbol names, portable paths). One test: `ctest --test-dir build/host -R <name>`.
`host_smoke` has a timing-sensitive lifecycle step that can fail on a loaded
host; rerun before suspecting a change.

UI renders: `build/host/tests/ui_render_tool <out-dir>` writes raw 1024x574
ARGB8888 frames (`free.argb`, `guidance.argb`, `pin.argb`, `dev.argb`, ...).
Convert with Pillow (`Image.frombuffer('RGBA', (1024, 574), raw, 'raw', 'BGRA', 0, 1)`)
and look at them before claiming a UI change works. The UI fonts/icons are
generated by `backends/osmand/ui/assets-src/`.

## Evidence (separate repository)

Reverse-engineering evidence and its checks live in the sibling
`open_navicore-re` (`make`, `make qnx`, `make replay` there, with
`PRODUCT=<this checkout>`). Run it when contracts change.

## Before committing

- `make test` passes, and `make` for anything that runs on the radio.
- `tests/check_portable_paths.py` (in `make test`) rejects workstation
  paths in tracked files (mount points, home directories) in code, docs
  or skills: use relative paths and variables.
- Public ABI changes (`include/open_navicore/*.h`) stay append-only; see
  `docs/design/api-ui-restrictions.md` and `docs/technical.md`.
